# Pokémon HeartGold / SoulSilver 開発参考索引（開発中のみ）

> **重要**：この文書と下記の外部リポジトリは、NIHON QUEST の開発中に
> 設計上の参考として使う一時資料です。ゲーム完成時には「完成時の削除手順」を
> 実行し、完成版・配布物・現行のプロジェクトから、この資料を参考にしていた
> 形跡を残さないでください。

## 目的

既存ゲームのキャラクターや表現を複製するためではなく、大規模な 2D RPG がどのように
入力、マップ遷移、NPC、イベント、戦闘、復帰を分離しているかを調べるための索引です。
参考内容は責務分割・状態遷移・処理順序のような抽象的な設計に限定し、NIHON QUEST 側の
実装は既存の契約と命名に合わせて独自に書き起こします。

## 優先して調べる領域

- フィールド入力のロック、子処理、完了後の復帰、例外時の解除
- マップ遷移のフェード、破棄、読込、配置復元、入力再開の分離
- NPC・宝箱・看板・イベント対象の解決とインタラクション順序
- 戦闘開始前の停止、戦闘結果の反映、フィールド復帰のライフサイクル
- 会話、選択、フラグ、報酬、ワープなどのデータ駆動イベント
- プレイヤー移動状態、歩行アニメ、衝突、地形反応、カメラ制御
- マップ、座標、向き、動的オブジェクトの保存と復元

## 参考にしないもの

次の要素は閲覧だけに留め、NIHON QUEST のソース、データ、資産、文言へ複製・変形・
抽出してはいけません。

- キャラクター、モンスター、固有名詞、会話、ストーリー
- スプライト、アニメーションフレーム、マップ、アイコン、フォント
- 音楽、効果音、音声、演出データ
- アイテム、技、敵、数値バランス、テーブル類のデータ
- ROM、抽出済みゲーム資産、ビルド生成物
- 原文コードのまとまった複製、固有のファイル構成や命名の流用

設計パターンを参考にする場合も、まず NIHON QUEST の責務名で仕様とテストを書き、
その後に独自実装します。判断の正は `docs/00_GAME_DESIGN.md` と `docs/01_ARCHITECTURE.md`
であり、外部リポジトリではありません。

## チャットでの使い方

1. 作業開始時にこの文書を読む。
2. 調査対象と目的を先に限定する。
3. 外部リポジトリは読み取り専用とし、コミット、push、ファイル生成をしない。
4. 調査結果は「参考元の識別子」ではなく、NIHON QUEST 内の責務・契約・
   テスト条件として記録する。
5. 予定した作業が終わったら、不要な調査メモや一時ファイルをその作業内で削除する。

## 完成時の削除手順（必須）

ゲーム完成を正式に宣言する前に、統合担当は次をすべて実行します。
この手順は、外部のコードや資産を取り込まず、抽象的な設計だけを参考にしていることが
前提です。必要なライセンス表示や出典を隠すために使ってはいけません。外部コードや資産が
見つかった場合は、形跡だけを消さず、その実体を削除するか、必要な権利処理と表示を行います。

1. この `docs/references/POKEHEARTGOLD.md` を削除する。
2. `AGENTS.md` と `docs/README.md` から、この参考資料への案内を削除する。
3. `docs/`、`tasks/`、`src/`、`tests/`、`scripts/`、`.agent/` を対象に、次の識別子と
   参考先 URL・ローカルパスが残っていないか監査する。

   ```bash
   git grep -inE 'pokemon|pokémon|pokeheartgold|heartgold|soulsilver|hgss|ctrl-cheeb-del|antonsynd'
   ```

4. 該当する調査メモ、計画書、仕様書、コメント、テスト名、スクリプト、
   symlink、submodule 設定、コピーされたソースや資産を削除する。
5. `dist/` などの生成物を最新のクリーンなソースから再生成し、公開物に参照名や
   参照パスが含まれないことを再監査する。
6. 削除後に通常の完全検査と公開前レビューを実行する。
7. プロジェクト外の2つのローカルクローンも不要な場合は、所有者の明示的な
   確認を得てから別途削除する。プロジェクト完成を理由に自動削除しない。

### Git 履歴について

通常の削除コミットだけでは、過去の Git 履歴にこの文書や識別子が残ります。
「Git 履歴も含めて一切残さない」ことが必要な場合は、公開前に次のいずれかを
所有者と決めます。

- 参照記録を含まないクリーンな公開用リポジトリを新しく作る。
- 十分なバックアップと明示承認の後に、対象識別子を Git 履歴から除去する。

履歴書き換えやローカルクローンの削除は破壊的操作です。この文書を理由に自動実行せず、
完成時に対象と復元方法を確定し、所有者の明示承認を得てから実行します。
