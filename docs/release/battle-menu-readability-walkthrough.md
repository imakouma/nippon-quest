# バトルメニューの読みやすさ

## 対象と表示方針

小学生向けの横画面バトルで、道具・仲間の名前、個数、HPを読みながら選べるようにする。
基点は `83dbbb89`。専用の `codex/main-battle-audio` で作業し、別チャットの未コミット変更は取り込まない。

参照を既存の戦闘画面、技一覧、承認済みのバッグ画面に固定する。
Referoの既存UI向け手順と同梱のfocus・scrollガイドに従い、外部アカウント・有料調査は使わない。

| 判断 | 参照・理由 |
| --- | --- |
| 白い太枠・黒い背景・PixelMplusを維持 | 既存バトルとGDD §8。新しい見た目を持ち込まない |
| 道具の一覧と説明を左右に分ける | 既存の技一覧。説明文で操作領域が縮まらない |
| 交代は1列、HPバーと数値を確保 | バッグの広い一覧と既存のHP表示。名前と状態を同時に読む |
| 矢印移動を見た目の1列に一致させる | 既存の黄色い選択枠。1回押すごとに隣の行へ移動 |
| 説明は独立してスクロール可能 | Refero craft-detailsのfocus・scroll方針。説明の矢印操作では選択を動かさない |

背景・キャラクター配置・右下のHP枠・戦闘ロジック・教材・セーブ形式は変更しない。

## 再現できた問題

- 道具の長い説明で一覧の可視高が28pxになり、40pxの1行さえ全表示できない。
- 2列の道具一覧は640pxの枠に対して660pxになり、右端の個数が欠ける。
- 交代の2列一覧が横にはみ出し、「せんとうちゅう」の表示でHPバーが押し潰される。
- 縦並びのコマンドで下矢印を押すと「わざ」から「いれかえ」へ飛ぶ。

## 実装

- 道具の説明を一覧の右側へ移し、長い名前は折り返す。
- 交代を1列にし、HPバーに最小幅と現在値/最大値を表示する。
- コマンド・技・道具・交代の矢印移動を1行ずつに統一する。
- 自動スクロールで静止中のポインターが別の行へ乗っただけでは選択を変えず、実際にポインターを動かしたときだけ追従する。
- 既存のクリック、戻る、使用不可表示、一覧スクロールを維持する。

## 検証

修正前のE2Eで高さ・横はみ出し・矢印選択の失敗を確認。
`tests/e2e/battle-menu-readability.spec.ts` は実際の道具・仲間の定義を一時的な遭遇に設定し、保存データを変更せずに検査する。

- `pnpm lint` / `pnpm check:architecture` / `pnpm validate:content` / `pnpm build`: 成功。
- `pnpm test`: 114ファイル・1,232件成功。
- `E2E_PORT=4175 E2E_REUSE_SERVER=1 pnpm test:e2e:battle`: 初回17件成功、3件失敗。説明欄の操作対象を明示し、フォント読込を待ち、各行の寸法を一括取得するよう新規テストを整理した。
- 失敗3件とコマンド移動を独立して再実行し、4件すべて成功。既存の戦闘進行テストは製品コード・テストを変更せず再実行で成功した（初回は2秒のクリック待ちでタイムアウト）。戦闘E2E20件の成功を再実行を含めて確認。
- 説明欄のフォーカス・スクロールを含む960px検査をさらに2回連続実行し、両方成功。最終テストコードの `tsc --noEmit` と整形・lint検査も成功。
- 道具・交代を960×540と640×360で確認し、320・768・1024・1440px幅への変更でも一覧の横はみ出しと末尾の可視性を検査。使用不可の仲間を選んでも交代しないこと、戻る操作、実行時・コンソールエラーなしも確認。
- ミューテーション確認: 説明欄の矢印キー伝播抑制を一時的に反転すると、選択位置の維持を検査するE2Eが失敗。正しい実装に復元済み。
- レビュー: 表示と操作の整合性、読みやすさ、テストの検出力、追加の通信・保存処理がないこと、既存レイアウトの再利用を確認。依存追加・契約変更はない。
- Graphifyは `graphify update . --no-cluster` でコードのみ更新。外部LLMは未使用。

実画面の確認画像は、同E2Eの `test-results/…/item-menu.png` と `swap-menu.png` に出力する（Git管理外）。再実行時の出力先は `/private/tmp/nihon-quest-menu-e2e-recheck/`。
