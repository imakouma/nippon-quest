# ニホンクエスト（NIHON QUEST）

小学生向け、**ゲームが主体・勉強が要素**のドット絵 RPG。日本 47 都道府県が地方ごとの島に分かれた世界を旅する。

Phaser 3 + TypeScript + Vite + Preact / ブラウザで動作 / ログイン不要・端末内セーブ。

---

## 3行でセットアップ

```bash
pnpm install
pnpm dev        # → http://localhost:5173
```

Node 20 以上、pnpm 10 以上。`pnpm dev` でタイトル画面、`http://localhost:5173/playground.html` で問題UIの単体確認と、問題の一覧（教科・学年・タイプ・単元・ことばで しぼりこみ、行を押すとその問題を表示。`?q=<問題 id>` で直接ひらける）ができます。開発サーバでは `window.__nq` に `Phaser.Game` が入ります（コンソールや E2E から中を見る用。本番ビルドには入りません）。

## この設計の一番大事なところ

**問題の中身（content）／問題の見た目（renderers）／ゲーム本体（core・scenes）は、3人が同時に別々に触っても衝突しない**ように分けてあります。接点は `src/questions/contracts.ts` の型だけです。

```
[問題作成者] content/questions/*.json  ──検証──▶ 各レンダラーの schema
                                                      │
[UI担当]     src/questions/renderers/<type>/  ────────┘
                     │ QuestionResult { score: 0.0〜1.0 } だけを返す
                     ▼
[ゲーム本体] src/core, src/scenes  ← score 以外は一切見ない
```

この境界は **ESLint とユニットテスト（`tests/unit/boundaries.test.ts`）の両方で機械的に守っています**。AI が設計を崩そうとすると、テストが落ちます。落ちたときに安易に緩めないでください。

守られていること（テスト済み）:

1. `content/` に `.ts`/`.js` を置けない
2. レンダラーは Phaser・GameState・localStorage を import できない
3. `src/core` と `src/scenes` に問題タイプ名（`"choice"` など）が現れない
4. `Math.random` が使われていない（対戦の決定論性のため）
5. `contracts.ts` は zod 以外に依存しない

## 問題を1問足してみる（問題作成者向けの最短手順）

1. `content/questions/sansu/g1/tashizan.json` を開く
2. 配列に 1 要素足す（`"$schema"` を書いておくと VS Code で補完が効きます）
3. `pnpm validate:content` を実行 → OK が出れば完了
4. `/playground.html` でその問題を選んで、実際に解いてみる

**コードは一切触りません。** ビルドも不要で、ファイルを置いてリロードすれば反映されます。

## 問題タイプを1種類足す（UI担当向けの最短手順）

1. `src/questions/renderers/<type>/` を作り、`schema.ts` と `index.ts`（`QuestionRenderer` を export）を書く
2. `renderers/registry.ts` に 1 行追加
3. `content/questions/_samples/<type>.json` にサンプルを 3 問
4. `pnpm gen:schemas` → `/playground.html` で確認

**この 4 つ以外のファイルを触る必要はありません。** 触る必要が出たら、それは設計がずれているサインです。

## Antigravity での進め方

1. このフォルダを Antigravity で開く（`.agent/rules/nihonquest.md` が自動で読まれます）
2. `docs/00_GAME_DESIGN.md` と現在のテストを正として、未完了項目を小さな単位で実装する（`docs/02` の古いStep表だけで現在地を判断しない）
3. Implementation Plan を読んで承認 → 実装 → `pnpm check` が通ることを確認 → コミット

仕様を変えたいときは、チャットで指示せず **`docs/00_GAME_DESIGN.md` を直してから**「GDD が変わったので追従して」と言ってください。これをやらないと、AI は docs と矛盾したコードを書き始めます。

モデルの使い分けは `docs/02` §0.2（計画とコンテンツ量産は Gemini、TypeScript 実装とテストは Claude、画像編集は ChatGPT）。

## CI とデプロイ

`.github/workflows/ci.yml` が push / PR で lint・test・validate・build を回し、スキーマの再生成漏れも検出します。`main` に入ると GitHub Pages へ自動デプロイ（`BASE_PATH` はリポジトリ名から自動設定）。

## ライセンスと素材の注意

- フォントは **PixelMplus12**（M+ FONT LICENSE、`src/ui/fonts/`）を同梱。文字の大きさは 12 / 24 / 36 / 48px だけ使う（ほかの大きさはドットがにじむ）。BGM・効果音は未同梱（`docs/README.md` の「他に必要なもの」）。
- 絵の規格・パレット NQ-48・画像生成プロンプトは `docs/06_ART_BIBLE.md`。
- **ご当地キャラ・企業ブランド・アニメキャラは画像にも名前にも使わない。** 実在人物・宗教施設は敵にしない。詳細は `docs/03` §9、`docs/05` §4。
- 個人情報は取得しません。セーブは端末内のみ。
- マップの地形は実在の地理データから作っています（`pnpm gen:terrain`）。出典は **地球地図日本（国土地理院）** の県境・海岸線（dataofjapan/land 経由）、**国土地理院 標高タイル**、Natural Earth（琵琶湖）。公開するときはクレジットに出典を明記してください（地球地図日本を営利目的で使う場合は、国土地理院への利用報告も必要）。
