# 問題レビューでの保存

## 目的と受け入れ条件

- 開発用の問題レビュー画面で編集した内容は、保存ボタンを押すまで問題ファイルに反映しない。
- 保存成功後は元の問題ファイルに残り、画面を再読込しても同じ内容を表示する。
- 保存失敗時は理由を表示し、編集中の内容を保持する。未保存の状態で問題を切り替える場合は確認する。
- 他の開発者が同じファイルを変更していた場合は上書きせず、利用者に知らせる。
- 問題 ID、単元、問題タイプを変更せず、対象以外の問題や編集対象外のデータも保持する。
- 教科・学年は現在の単元とファイルの配置と一致する必要がある。一致しない変更は保存せず理由を表示する。
- 問題とタイプ固有のデータを検証し、不正な内容は保存しない。
- 保存先は開発環境の問題ファイルに限り、本番ビルドには書き込み機能を含めない。

## 実装と境界

- `src/tools/` の編集画面、開発用サーバー、対応するテストを対象とする。
- 書き込み先はサーバー側で検証し、パストラバーサルや外部サイトからの書き込みを拒否する。
- 保存は競合検出と安全なファイル置換を伴う。生成済みコンテンツの更新方法も検証する。
- 契約・スキーマは変更しない。新規依存を追加しない。

## 検証

- 単体・統合テストで正常保存、不正データ、競合、対象外データの保持、書き込み先の制限を確認する。
- 実ブラウザで編集、保存、再読込、失敗時の下書き保持を確認する。
- `pnpm check:fast` と関連テストを実行する。統合担当は統合後に完全検査を実施する。
