# 問題レビュー全体の連続的な比例サイズ

## 要求と対象

- ユーザーが求めた「全て連続的で相対的なサイズ」を、現在の問題レビュー画面全体に適用する。
- 対象はヘッダー、問題一覧、問題プレビュー、編集フォーム、結果欄。問題本体は既存の共通questionViewportを引き続き利用する。
- 表示幅ごとの列切替・文字サイズの下限上限・固定pxによる別倍率を廃止する。
- 保存形式、問題データ、採点、ゲーム本体の別画面は変更しない。

## 表示方針と実装

- Referoの既存デザイン維持手順・typography資料と、現行の狭幅プレビューを基準にする。既存の色、書体、カード、時計画像を維持する。
- 一覧とレビューは常に縦1列。横2列の縮小で問題がさらに小さくなるのを避ける。
- 現行の幅520pxを基準に、ルート文字サイズを画面幅の比率で決定する。文字・余白・罫線・アイコン・フォームはrem、コンテナは%/frで同じ倍率へ統一する。
- `%`の文字指定は親文字サイズ基準なので、それだけで画面幅比例にならない。共通のルート倍率を使う。
- 画面幅に比例してPCでは大きく、スマホでは小さくなる。文字を独立した下限で固定せず、ブラウザのピンチ拡大は妨げない。

## 検証と手順

1. 320〜1440px、既存境界340/520/600/768/820/960/1100/1200の前後で、文字・時計・ボタンの画面幅に対する比率を測るE2Eを追加。修正前に320pxで失敗を確認済み。
2. 相対寸法と一貫した配置に修正。検索・編集・採点を既存E2Eで検証。
3. `pnpm check:fast`、`pnpm typecheck:tests`、スマホ向け/問題viewport/Playground E2E、build、独立レビューを実施する。
4. 統合後は4174を最新版で再起動し、アプリ内ブラウザで確認する。

実機確認はユーザーの指定に従い行わず、Android/Chromium・iPhone/WebKitのブラウザ検証と区別して報告する。

## 確認結果

- Android/Chromium 15件成功（25種類の幅での比例サイズ、検索200件、全9形式、タップ・入力）。
- Playground・問題viewportの既存E2E 46件成功。横2列を前提としていた2件は新仕様の縦配置・基本情報2列に更新。
- check:fast、typecheck:tests、開発ツール付きbuild成功。フォームの関連単体テストは対象なしのため、編集・保存のE2Eで検証。
- 独立レビューの検索一覧の高さ制限と既存E2Eの指摘を解消。
- 端末の罫線描画の丸めで数pxの差は出るため、回帰検査では文字比率を厳密に比較し、枠の累積丸めは5 CSS px未満のみ許容する。
- 小さい画面では編集欄の補助文字も比例して小さくなる。PCのページズームはvwと相殺するため、文字拡大の改善は今回の成果に含めない。
