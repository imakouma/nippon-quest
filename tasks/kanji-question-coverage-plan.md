# Implementation Plan: kanji-question-coverage

## Overview

承認済みの `SPEC-kanji-question-coverage.md` に基づき、検証済みの小学校配当1026字から、書き・音読み・訓読みを各1026問、合計3,078問の正規問題群として生成する。生成処理、30問セット、単元、タグ、監査を再現可能にし、問題数を満たすために架空の読みや推測した熟語読みを使わない。

問題データは自動生成されるため、実装コードと少数の代表テストを先にレビューし、全生成物は監査で機械検証する。フォルダUIは次の `kanji-folder-taxonomy` まで変更しない。

## Architecture Decisions

- 正規入力は `content/kanji/readings.json` だけとし、既存問題本文から音訓を推測しない。
- 問題契約とレンダラーは変更せず、書きは既存 `kanji-trace`、読みは既存 `choice` を使う。
- 既存の書き3問はIDと内容を保ち、明示タグを付けて正規問題として数える。生成側では同じ漢字を重複させない。
- 生成ロジックは純粋関数としてテストできる形にし、ファイル書込は許可された `kanji-writing`、`kanji-onyomi`、`kanji-kunyomi` ディレクトリだけに限定する。
- `scripts/question-layout.ts` の30問分割規則を再利用し、生成物のファイル名やセット構造を独自実装しない。
- 3〜6年には正規単元 `kokugo.gN.kanji` を追加し、legacy単元へ新規問題を混ぜない。
- 読み問題は、まず各漢字の最初の読み、次に別読みを採用する。不足時だけ正しい既存読みを異なる誤答集合で復習し、同一問題を重複させない。
- 全選択肢を平仮名にし、対象漢字が持つ別の正答読みを誤答にしない。
- 通常の `validate:content` にカバレッジ監査を統合し、将来の欠落・誤タグ・30問超過をビルド前に失敗させる。
- UI変更はないが問題はユーザー向けなので、最後に旧確認ビューではなく新しい `playground.html?q=...` で代表問題を実際に表示・回答する。

## Verification Strategy

1. 生成関数が存在しない状態で、件数、決定性、タグ、選択肢、代表例の失敗テストを確認する。
2. 各増分で対象カテゴリだけを生成し、関連テストとコンテンツ検証を通してからコミットする。
3. 生成を2回実行し、2回目の `git diff` が空になることを確認する。
4. 独立した監査スクリプトで、生成コードと異なる経路から件数、正解、ID、ファイル上限を検査する。
5. `pnpm test:fast` で学習グラフや既存問題への回帰を確認し、`pnpm build` で問題追加後のバンドルを検証する。
6. 最新ビルドの作業用サーバーを再起動し、新しいPlaygroundページで各学年の書き・音読み・訓読みを確認する。

## Risks and Mitigations

| Risk                                          | Impact | Mitigation                                                                                   |
| --------------------------------------------- | ------ | -------------------------------------------------------------------------------------------- |
| 3,078問の生成物が大きく、目視レビューできない | 高     | 生成コードと代表例をレビューし、全件は独立監査・件数・ハッシュ差分で検証する                 |
| 複数の正しい読みを誤答として出す              | 高     | 対象漢字の全音読みまたは全訓読みを誤答候補から除外し、テストと監査で固定する                 |
| 訓読み数が足りない学年で架空の読みを作る      | 高     | 正しい読みだけを再利用し、異なる誤答集合の復習問題として補う                                 |
| 新規単元がカリキュラム参照を壊す              | 高     | 3〜6年を正規IDで追加し、`validate:content`、学習グラフテスト、`test:fast` を各段階で実行する |
| 生成処理がlegacy問題を上書きする              | 高     | 書込・削除先を3種類の生成専用ディレクトリへ固定し、パス検査をテストする                      |
| 問題追加で起動・ビルドサイズが悪化する        | 中     | ビルド出力を前段階と比較し、既存性能ゲートを通す。必要なら後続で読込分割を別仕様にする       |
| 自動生成問題が単調になる                      | 中     | 同一の漢字・正解・選択肢集合を禁止し、教材レビュー待ちを明示する                             |

## Rollback

生成専用ディレクトリ、3〜6年の正規単元、既存3問へのタグ、生成・監査スクリプトだけを独立コミットで戻せる。legacy問題、正規漢字データ、問題レンダラー、保存データは変更しない。
