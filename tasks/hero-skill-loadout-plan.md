# 主人公の技編成 実装計画

基点: `codex/skill-battle-system` の 083c732de6e04657c198479dd06777c4430c2912。仕様: `SPEC-hero-skill-loadout.md`。

## 保存形式を変更する理由と影響

現在の `player.skills` は習得済み技の一覧で、戦闘時に装備の付与技と自動バーストが加わる。習得済みと使用中を分けるため、`GameState.player` に通常4枠・チャージ2枠の編成を追加し、保存スキーマをv14から更新する。`player.skills` はそのまま保持し、既存セーブの移行・新規ゲーム・中断戦闘の再開・保存の検証を変更する。コンテンツの技スキーマと問題契約は変更しない。

移行時は習得通常技の先頭4つを選び、国語と算数のバーストを初期セットする。移行関数にはコンテンツが渡されないため、既存データの分類に依存する選択はコンテンツ読み込み後の純粋関数で確定し、旧セーブを失わないよう明示的な未初期化状態を区別する。中断中戦闘には保存済みの戦闘状態を使い、次の戦闘から新編成を適用する。

## 実装順・受け入れ条件

1. **編成の純粋ロジックと移行**：`src/core/progression/` に候補・分類・重複・枠上限・装備の有効性と最低1通常技を扱う関数を設ける。保存スキーマ、移行、新規ゲームを更新する。旧セーブの全技保持、初期4+2、空き枠、無効な技、装備解除、中断戦闘を先にテストする。
2. **戦闘への適用**：`src/core/battle/setup.ts` と `commandEvaluation.ts` でセットした主人公の技のみを表示・使用可能にする。`factory.ts` の装備技自動付与と教科バーストの自動追加が6枠を迂回しないよう調整する。仲間の手動技・自動技、装備能力、セーブ済み戦闘には影響しない。戦闘テストで主人公6枠、装備、バースト、仲間を確認する。
3. **編成画面**：`もちもの・へんせい` の主人公詳細から、枠と候補を見て設定・解除できる画面を開く。UIには表示モデルとコールバックを渡し、Sceneや保存先を直接参照しない。技名、教科、威力、ゲージ、命中率、追加効果を表示し、キーボード・タッチ・小画面を確認する。変更を保存し再起動後も維持する。
4. **総合確認と記録**：関連Vitest、旧セーブ・中断戦闘の回帰テスト、実ブラウザでの編成・再読み込み・戦闘確認を行う。`pnpm lint`、`pnpm check:architecture`、`pnpm test`、`pnpm validate:content`、`pnpm build` を実行し、他チャットの重い検査と同時に走らせない。仕様書とウォークスルーを更新し、専用ブランチへコミットする。

## 注意点

- 既存の装備由来技は装備が外れると選択不可にするが、習得済みであれば失わない。
- 選択済みバーストの教科に対応する使用可能技がなくなった場合は枠を安全に無効化し、再編成できるようにする。
- 主人公が常に戦えるよう、使える通常技がない変更は拒否する。通常技が元々ない異常な旧セーブは移行時に既存の初期技を保護して復旧する。
- 命中率・追加効果は先行コミットを維持する。新規依存や共有ブランチへの直接マージは行わない。
