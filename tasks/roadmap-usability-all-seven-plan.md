# Implementation Plan: 学習ロードマップの7項目改善

## Dependency Order

表示契約テスト → フィルタと概要 → 地図の選択・ロック・ヒント → CSS → E2E → 全検査 → 実画面QA → コミット。

## Phase 1: Regression contract

- [x] 既存のスライダー・略称・`aria-pressed` 前提テストを、新しい要件へ置き換える。
- [x] おすすめ、情報ボタン、前提単元移動、操作ヒント、最小パンの失敗テストを追加する。
- [x] focused unit testが意図した理由で失敗することを確認する。

## Phase 2: Filters and overview

- [x] 学年・学期を独立したボタングループへ変更する。
- [x] 教科名を全文表示へ統一する。
- [x] 全教科概要に「つぎのおすすめ」を追加する。
- [x] 情報ボタンと説明パネルをタッチ・キーボード対応にする。

## Phase 3: Map interaction

- [x] 選択時の中央寄せを、画面外だけの最小パンへ変更する。
- [x] 前線単元の実名を詳細でも伏せる。
- [x] 前提単元を選択可能なボタンにする。
- [x] 初回ジェスチャー説明を表示し、操作時に消す。
- [x] 単元の `aria-pressed` を廃止し、ボタンとしての選択説明へ変更する。

## Phase 4: Visual implementation

- [x] 2段フィルタと全文教科名を960×540に収める。
- [x] おすすめを黄色の主要行動として概要の先頭に置く。
- [x] 48px操作対象、`focus-visible`、狭幅レイアウトを維持する。
- [x] `prefers-reduced-motion` で新規モーションを抑える。

## Phase 5: Verification and handoff

- [x] focused unitとfocused E2Eを通す。
- [x] mutation testで新規テストの検出力を確認する。
- [x] 必須5検査をすべて通す。
- [x] 最新ビルドの一時プレビューを4175以降で起動し、実ブラウザで確認する。
- [x] コードレビューを行い、P0〜P2を解消する。
- [x] 独立コミット、walkthrough、最終報告を作成する。

## Risks

- フィルタが縦に増えて地図が狭くなる: 1行48pxの密度と狭幅折り返しを実画面で確認する。
- 選択ノードのDOM寸法が取れない: 基準寸法へフォールバックし、ユニットテストで境界を固定する。
- 初回ヒントがテスト間で残る: アプリセッション内だけのモジュール状態とし、テスト用リセット関数を公開せず振る舞いで検証する。
- 前提単元がフィルタ外: 既存の直接前提コンテキスト追加を維持し、存在するものだけボタン化する。
