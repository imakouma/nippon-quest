# Implementation Plan: 仲間化アイテム「むすび玉」

## Overview

青森の町で購入を教わり、全町で補充でき、バトル中に問題を解いて仲間化へ挑戦できる一連の導線を追加する。既存の問題回答型「さそう」、敵専用好物、岩手の限定相棒は残し、共通捕獲アイテムだけを新しい縦の機能として足す。

既存の `tasks/plan.md` と `tasks/todo.md` には別作業の未完了項目があるため上書きせず、本機能はこの計画と `tasks/musubi-dama-todo.md` で追跡する。

## Architecture Decisions

- `Item.use` にデータ駆動の仲間化効果を追加し、Sceneで `common-musubi-dama` を文字列分岐しない。
- 捕獲判定は `src/core/battle/` の純粋関数へ置く。HP・敵固有率・score・timeMs・アクセシビリティ倍率だけを入力にする。
- UI上は既存の「どうぐ」一覧を再利用する。仲間化不可対象では無効理由を表示し、問題も消費も発生させない。
- むすび玉用の問題は既存のバトル問題枠を使い、敵の県タグとプレイヤー学年に合う候補を選ぶ。
- `Battle.ts` は既に行数上限付近のため、問題起動と捕獲コマンド生成は近接モジュールへ抽出し、Sceneの増加を相殺する。
- 全町共通在庫は `shopStock` が明示在庫・自動在庫のどちらにも重複なく加える。
- 青森の導入状態は既存の `progress.counters` / `eventsDone` を使い、セーブスキーマ変更を避ける。
- 初購入後の完了判定は購入結果を基準にし、会話を閉じる前に保存して中断時の二重付与を防ぐ。

## Dependency Graph

```text
Item契約・商品データ
  ├─ 全町ショップ在庫
  ├─ 捕獲確率・消費ロジック
  │    └─ バトル問題/UI接続
  └─ 青森の購入導入
       └─ 岩手物語との整合

全縦断経路 ──> E2E・実画面検証
```

## Risks and Mitigations

| Risk                                           | Impact | Mitigation                                               |
| ---------------------------------------------- | -----: | -------------------------------------------------------- |
| 速さ重視が低学年・アクセシビリティ利用者に不利 |   High | 速度は加点だけにし、制限時間倍率に応じて基準時間を伸ばす |
| 問題中断でアイテムだけ減る                     |   High | 解答確定後にだけ純粋ロジックへ捕獲コマンドを渡す         |
| 全町共通在庫が明示ショップと重複する           | Medium | itemIdで一意化するユニットテストを置く                   |
| 岩手の既存物語と矛盾する                       | Medium | 市販品と特別な古い三つを文言で区別する                   |
| `Battle.ts` / `Overworld.ts` の行数上限超過    |   High | 機能別モジュールへ置き、Scene変更は調停の数行に限定する  |
| 既存セーブで導入が永久に出ない／毎回出る       | Medium | 未購入・未完了・現在マップの組合せを純粋関数でテストする |
