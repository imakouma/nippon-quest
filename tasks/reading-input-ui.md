# 読み方入力UIの改善

- 基点: 共有main `af161643`。担当: text-inputの読み問題表示、生成元の案内文、検証。
- 対象: `kanji:reading:*` タグの文字入力問題（現在は小1音読み80問）。算数等の入力UIは維持。
- 通常はひらがなの案内を出さない。ひらがな以外の確定入力で案内を出し、採点せず修正できる。IME変換中は警告を抑制。
- 参照固定: 既存ゲームの濃紺・角形枠・黄色の操作色を主軸にする。ユーザーのスクリーンショットの過剰な余白を解消。
- Referoの同梱Typography「Vertical Rhythm」とCraft Details「Forms/Error Handling」を参照。例文→入力→送信を近接配置、案内は入力付近、フォーカスとaria-invalidを維持する。ライブReferoツールは未提供。
- 例文を40px、入力を32px、ラベルを24pxで階層化。未注釈の漢字を黄色と薄い背景で強調する。下線は「一」と「二」を混同しやすいため使わない。正解のルビは表示しない。新しい画像・フォント・依存は追加しない。
- 手順: 再現テスト→検証と配置の実装→関連単体/型/lint/教材/build→4幅の実ブラウザとレイアウト回帰→共有版統合と正規プレビュー。

- `pnpm test`: 243ファイル、2302テスト成功。lint、依存境界、テスト型検査、教材検証、開発ツール入りbuildも成功。
- ブラウザ: 音読み入力・question-viewport・battle-question-audit代表検査の32件成功。強調背景の最終調整後も、4幅とIME/長文の5件成功。
- 案内の表示/非表示でボタン位置が変わらないことを検証。入力エラーを送信しても採点せず、そのまま直せる。
- 最終画面: [通常](../test-results/g1-onyomi-1440.png)、[不正な入力](../test-results/g1-onyomi-invalid.png)、[長い例文](../test-results/g1-onyomi-long.png)。
- 自己レビュー: 既存の読みタグで対象を限定。契約/schema/新規依存の変更なし。算数や他の文字入力、既存の読み上げ/時間切れ/IME確定Enterの処理を維持。
