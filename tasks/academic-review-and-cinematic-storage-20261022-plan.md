# 学術レビュー運用・動画アセット管理計画（2026-10-22）

## 目的

人間による教材の学術承認を代行せず、未承認教材を安全に確認・記録できる運用を整える。同時に、Git の通常履歴へ入れられない動画・制作素材を、改ざん検知できる一覧と明示的な保存方針で管理できる状態にする。

## 前提と境界

- 学術的な正誤と承認者名は人間だけが決める。自動処理は候補抽出、ハッシュ計算、入力検証、台帳更新補助に限定する。
- 既存の `content/quality/academic-reviews.json`、`imports/academic-review-queue.json`、`pnpm audit:academic-review` を正として拡張する。
- 動画・制作素材は今回アップロードしない。外部サービスの契約、資格情報、課金設定、公開範囲の変更もしない。
- Git LFS は GitHub Pages から直接利用できないため、ゲーム配信用アセットと制作原本を分けて判断する。
- 依存パッケージ、問題契約、schema は変更しない。

## 設計判断

- 教材承認は 1 ファイル単位で記録し、記録時に現行ファイルの SHA-256 と既存出典 ID を自動検証する。
- CLI は明示的な承認操作にだけ使い、レビュー内容を自動判定しない。実行後も既存の strict 監査をリリースゲートにする。
- 動画素材は「Git に置くか」ではなく「制作原本・配信成果物・メタデータ」の3層で扱う。
- 今回は相対パス、サイズ、SHA-256 を持つ再現可能なローカル目録を作り、保存先の最終採用は ADR を Proposed として残す。
- 現時点の推奨は、制作原本を外部オブジェクトストレージ、配信成果物を同ストレージ/CDN、Git には目録と参照情報のみ置く構成。短期の受け渡しには GitHub Release を候補に残す。

## 依存関係

既存監査・台帳 → 承認記録 CLI と運用ガイド → strict 監査で確認

ローカル制作素材 → 目録生成 → 保存方式 ADR → 将来のアップロード実装（今回は対象外）

## タスク

### Task 1: 現状の固定

**受け入れ条件:**

- 未承認ファイル数・問題数と、動画素材の件数・容量・最大ファイルを再計測する。
- 既存台帳、監査コマンド、Git 除外方針との重複や矛盾を確認する。

**検証:** `pnpm audit:academic-review` とローカル素材目録の件数・合計サイズを照合する。

### Task 2: 学術レビュー記録の安全な導線

**受け入れ条件:**

- 対象ファイル、レビュー担当者、確認日、出典 ID を必須入力として台帳へ記録できる。
- 不明な問題ファイル、不明な出典、重複承認、不正な日付は台帳を書き換えず拒否する。
- 実ファイルの SHA-256 を自動記録し、人間の承認なしに項目を追加しない。
- レビュー担当者向け手順に Playground、一次資料、変化する事実、再監査を明記する。

**検証:** CLI の純粋ロジック単体テスト、`pnpm audit:academic-review`、`pnpm validate:content`。

### Task 3: 動画素材の目録と保存方式 ADR

**受け入れ条件:**

- 任意のローカル素材ルートから、相対パス・サイズ・SHA-256 を含む決定的な JSON 目録を生成できる。
- 目録にはローカル絶対パス、資格情報、署名付き URL を含めない。
- Git LFS、GitHub Release、外部オブジェクトストレージの制約・用途・公開リスクを公式資料に基づいて比較する。
- 保存先の契約と公開範囲は未決定として残し、実アップロードを行わない。

**検証:** 小さな一時ディレクトリを使う単体テスト、実素材 483 件の目録生成、秘密情報・絶対パス検査。

### Checkpoint: 統合確認

- 学術承認を自動化・捏造していない。
- 大容量素材が Git の通常履歴に追加されていない。
- 新しい依存、資格情報、外部アップロードがない。

### Task 4: 全体検査・レビュー・PR更新

**受け入れ条件:**

- 必須検査と関連監査が通る。
- 差分を正しさ、可読性、構造、安全性、性能の5軸で確認する。
- 変更を1つの追補コミットとして既存PRへ push する。

**検証:** `pnpm lint`、`pnpm check:architecture`、`pnpm test`、`pnpm validate:content`、`pnpm build`、`git diff --check`。

## リスクと対策

| リスク                                     | 影響 | 対策                                                                                       |
| ------------------------------------------ | ---- | ------------------------------------------------------------------------------------------ |
| CLI 実行だけで未確認教材を承認できてしまう | 高   | 人間の確認手順を必須化し、CLI は明示引数と既存出典の検証だけを行う。承認責任は担当者に残す |
| 目録にローカル情報や秘密 URL が混ざる      | 高   | 相対パスだけを書き、生成後に絶対パス・秘密らしい文字列を検査する                           |
| 外部ストレージ採用で課金や公開範囲が変わる | 高   | ADR を Proposed に留め、アカウント・課金・公開設定はユーザー承認後の別作業にする           |
| 1.3 GB の素材を誤って通常 Git に追加する   | 高   | 実バイナリは worktree 外のローカル退避先に維持し、コミット対象を明示確認する               |

## 今回決めないこと

- 外部ストレージ事業者と料金プランの契約
- バケット名、リージョン、公開 URL、認証方式
- 483 件の制作素材を公開するか、最終成果物だけを公開するか
- 教材内容そのものの承認
