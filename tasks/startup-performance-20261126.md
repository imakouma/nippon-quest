# 起動時間の計測

- 対象：統合 HEAD `cf8a3ac7` を取り込んだ作業版。Vite 開発サーバー、同一ブラウザ、キャッシュ無効、`?debug=battle&enemy=aomori-ringoron&lv=5`。
- 開発版コンテンツ読込：変更前 21.2 秒、変更後 0.74 秒と 1.94 秒。開発サーバー上の負荷により変動するため、端末一般の保証値ではない。
- 対策：開発版も現在の JSON から生成した一括応答を使う。実ファイルを毎回読み、生成済み bundle が古くても編集を反映する。失敗時は従来の個別取得へ戻る。
- 本番でも、問題 bundle とゲームデータを並行取得する。遅延したゲームデータを待たずに問題 bundle の取得が始まることを E2E で検証する。
- ブラウザで戦闘の敵登場とコマンド画面を確認。表示・操作に変更はない。

## 本番ビルドの比較

統合 HEAD `bf58cd90` を取り込んだ同一ソース・同一教材から本番ビルドを二つ作り、問題 bundle の先行取得と QuestionBank の並行 import だけを前後で切り替えた。Vite preview を localhost の別ポートで配信し、同じアプリ内ブラウザの同じタブで交互に5回ずつ開いた。ブラウザキャッシュを無効にし、サービスワーカーを迂回した。`?debug=battle&enemy=aomori-ringoron&lv=5` で新規開始し、文字送りの「次へ」が表示されるまでを計測した。計測用の同一スクリプトを両ビルドに一時挿入し、DOM の表示を記録した。

| 指標                             |   変更前 |   変更後 |
| -------------------------------- | -------: | -------: |
| タイトル準備（中央値）           | 0.786 秒 | 0.799 秒 |
| 戦闘メッセージ操作可能（中央値） | 5.855 秒 | 5.802 秒 |

いずれも `nq:boot-start` からの経過時間。「タイトル準備」はタイトル描画処理が開始した計測点であり、フェード完了ではない。戦闘操作可能の個別値は変更前 4.759、5.876、5.855、5.514、8.122 秒、変更後 5.539、5.553、6.121、5.802、8.824 秒。中央値の差は約53ミリ秒（約0.9%）だが、ばらつきが大きく、有意な短縮とは判断できない。ローカル配信のため、実際のネットワーク遅延がある環境での結果は未計測。戦闘開始直前のゲーム準備完了の中央値は変更前 1.800 秒、変更後 2.044 秒で、この試行ではむしろ遅い。戦闘コマンドまで操作でき、コンソールエラーはなかった。
