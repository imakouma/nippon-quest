# Implementation Plan: UI 継続改善ループ — 第1回

## Overview

実画面監査で確認した最優先問題は、縦向きスマートフォンで 960×540 のステージ全体が約 4 割に縮小され、文字とタップ対象が極端に小さくなること。ゲームの横向き設計は維持し、縦向きの小画面だけに端末を横にする案内を表示する。横向き・デスクトップ・既存ゲーム進行には影響させない。

## Evidence

- 390×844 の縦向き表示では、ゲームステージが画面幅 390px に縮小され、540px 高のうち約 219px しか使われない。
- タイトルの操作ヒントはキーボードのみを案内しており、縦向きタッチ端末で画面が小さい理由や解決方法が示されない。
- 既存 E2E は 640×540 と 960×540、および横向きタッチ画面を対象にしているが、縦向き表示の契約はない。

## Architecture Decisions

- Phaser の Scene やゲーム状態は変更せず、全画面共通の DOM/CSS 層で案内する。
- CSS の `orientation: portrait` と小画面条件を使い、JavaScript の向き監視や新しい依存は追加しない。
- 案内文は `content/i18n/ja.json` に RubyText として追加し、既存のユーザー変更と同じファイル内で競合しない位置へ小さく追記する。
- 案内はゲームを覆うが状態を破棄しない。横向きに戻せばその場で遊びを再開できる。

## Dependency Graph

`content/i18n/ja.json` の文言 → `src/main.ts` の案内 DOM → `src/ui/app.css` の表示条件 → Playwright の縦横向き検証

## Risks and Mitigations

| Risk                                                             | Impact | Mitigation                                                         |
| ---------------------------------------------------------------- | ------ | ------------------------------------------------------------------ |
| ソフトキーボード表示時など、意図しない縦長 viewport で案内が出る | 中     | 小画面かつ portrait のときだけ表示し、E2E で横向き非表示を固定する |
| 案内がゲーム状態を壊す                                           | 低     | Scene や保存処理に触らず CSS 表示だけにする                        |
| 既存の `ja.json` 変更と競合する                                  | 中     | 既存追記を保持し、独立キーだけを追加する                           |

## Next Candidate

### 第2回（完了）

タイトル画面の操作ヒントがキーボード操作だけを説明していたため、タッチ利用者にも「タップで けってい」と一目で分かる案内へ改善した。640×540 / 960×540 の両方で案内が見えることを E2E で固定した。

### 次の候補

### 第3回（完了）

タイトル画面の操作案内の下端がクレジットの上端へ 6px 重なっていたため、操作案内を 16px 上げた。640×540 / 960×540 の両方で実要素の矩形が重ならないことを E2E で固定した。

### 第4回（完了）

セーブがないときの「つづきから」は無効表示になるだけで理由を操作表示できなかったため、理由文をメニュー内へ常時表示した。無効項目から `aria-describedby` で関連付け、低学年でも読める文字サイズとコントラストに調整し、操作案内と重ならないことを E2E で固定した。

### 次の候補

物語画面の上部操作と状態表示を拡大し、オート状態とシーン位置を支援技術へ伝えるようにした。
