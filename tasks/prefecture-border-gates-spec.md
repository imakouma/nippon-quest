# Feature Specification: 全国の県境ゲートと実在交通網

**Status:** Implemented and verified
**Date:** 2026-10-18
**Integration branch:** `codex/integrate-prefecture-border-travel`

## Decision summary

全国移動を、現在の「中ボス後にワープホールで次県へ移動」から、地理に合った次の3種類へ置き換える。

1. 陸上で隣接する都道府県は、実際の共有県境に置く **県境ゲート** から移動する。
2. 海峡に実在する橋・海底トンネルは、現実の両端に置く **橋・トンネル入口** から移動する。
3. 橋のない海域は、現在運航している実在航路に基づく **港・フェリー**、または実在の鉄道から移動する。

架空の橋、海上の門、運航終了済み航路、理由のない瞬間移動は使わない。現実の距離を1:1で歩かせるのではなく、入口へ到達したあと短い移動演出を挟み、実在する反対側の入口へ着く。

## Objective

各都道府県の独立フィールドマップを保ちながら、日本がどこで陸続きで、どこを橋・トンネル・船・鉄道で渡るのかを、ゲームの移動そのものから学べるようにする。

現在は県外の陸地も陸として見える一方、県境の `x` タイルは衝突判定で止まり、中ボス撃破後はフィールド中央のワープホールから次県へ移動する。このため、見た目と移動方法が一致しない。変更後は次の体験にする。

- 県境には行き先が分かる門が見える。
- 閉じた門・交通入口は手前で止まり、開放条件を伝える。
- 開いた入口を使うと、地理的に正しい隣県または実在交通の到着地へ移動する。
- 北海道・四国・九州・沖縄も、実在する交通で本州や隣の章と結ぶ。
- 開発者モードでは、進行フラグを汚さず全国の門と交通リンクを使える。

## Canonical travel topology

### Land borders

- 現行の国土地理院由来地形データで実際に陸上境界を共有する **86組** を正規の県境リンクとする。
- 1組につき各県側に1か所、合計2つの対応ゲートを生成する。複数の道路や複数ゲートは今回の対象外。
- 門は自県の歩行可能な陸タイルに置き、隣に対象県の県外陸地 `x` がある、実際の共有境界付近でなければならない。
- 海 `.`, 湖 `~`, 離島どうしの近接、点で触れるだけの誤判定には陸上ゲートを置かない。
- 両側の門は同じ地理上の境界区間を指し、相互の `targetMap` と名前付き県境到着地点を持つ。
- 町から門まで、県内の正規進行で到達できる道路を生成する。門以外の `x` と水面は引き続き通れない。
- 生成器が条件を満たす配置を作れない場合、内陸や海へ黙って移動せず、県ペア名を含む検査エラーで停止する。

交通は、地理設備を示す `infrastructure` と、主人公の移動方法を示す `travelMode` の2軸に分ける。

架空の門や県間ワープを残さず、地方内の攻略順を実県境と実在交通で連続させるため、次の5地方を並べ替える。

## User-facing behavior

### Normal progression

1. 次県が陸続きなら、中ボス撃破地点にワープホールを出さず、対象県へ続く県境ゲートを開く。
2. 次の移動が実在交通なら、該当する駅・橋入口・トンネル入口・港を開く。入口には行き先と交通名を表示する。
3. 入口で決定すると、乗車・乗船確認のあと、スキップ可能な短い移動演出を表示して実在する反対側へ着く。
4. 交通入口は可能な限り到着県の開始地域内に置く。実在の港・駅が開始地域外になる場合は、到着地を表示したあと「県内移動」の短い演出を挟んで既定 `spawn` へ接続する。港・駅から説明なしに瞬間移動させず、地理上の到着県を別の県へ置き換えない。
5. 一度正規解放された物語順リンクは両方向で開いたままになる。
6. 物語順ではない県境門や交通リンクも地図には見えるが、通常モードでは両県を攻略するまで閉じる。未攻略県への近道には使えない。
7. 日本地図の高速移動は、実際に一度入った `visit:*` のあるマップだけに使える。地方ボス撃破だけでは次地方の最初の県を訪問済みにしない。
8. 章の入口が以前攻略した県にある場合、地方ボス撃破後の会話と日本地図で入口県を明示する。ワープ地点そのものを「次県」と偽装しない。
9. 四国編後の標準案内は、愛媛からしまなみ海道で広島へ戻り、山口の関門トンネル人道から福岡へ入る実在経路とする。三崎―佐賀関フェリーは、熊本を終えた時点で「次の大分へ入る別経路」として開く。

### Developer mode

- `dev:all` が有効な間は、進行フラグを書き換えず、全国の県境門と9つの実在交通リンクを即時に開く。
- 開発者モードを切ると、正規条件を満たしていない入口だけが閉じる。
- 開発者モードで未攻略県へ着いた場合も、`visit:*`、学習・ボス・地方クリアのフラグは永続化しない。地図の全表示はdev中だけの派生表示にする。
- dev中の現在地は確認用に更新できるが、devを切った時点で現在地が通常条件では不正なら、既存の訪問済みマップの安全spawnへ決定的に戻す。
- 到着直後に元の入口へ自動で跳ね返されない安全座標を使う。

## Unlock rules

門と交通リンクの開閉は保存する新しい真偽値ではなく、既存の進行状態から決定的に導出する。

1. `dev:all` が有効なら開く。
2. 承認済み攻略順のリンクは、出発県の `midboss.<area>` が完了していれば両方向とも開く。
3. 旧セーブ互換として、出発県の `progress.areaSigns` があれば同じく完了扱いにする。
4. 章間の正規入口は、直前地方までの playable 地方が攻略順どおり `islandsCleared` になったとき開く。不整合な旧devセーブで後半地方のフラグだけが残っていても章を飛ばさない。
5. 物語順でない隣接リンクと交通近道は、両端の県が完了し、両地方がそのセーブで解放済みの場合に開く。ただし章間の正規出口として表に定義したリンクは、直前地方の完了条件を優先する。
6. `ehime-oita-ferry` は、四国クリア済み、かつ `midboss.kumamoto` またはlegacy `areaSigns` の熊本完了がある場合だけ開く。`visit:oita-field` は解放条件に使わず、福岡・佐賀・長崎・熊本を飛ばせない。
7. 開発者モードの切替だけでは `midboss.*`、`areaSigns`、`islandsCleared`、`visit:*` を追加・削除しない。

## Runtime interaction

- 県境門と実在交通は、通常の町・ダンジョン `transition` や県内 `regionGate` と区別できる共通 `interPrefectureLink` モデルで扱う。
- リンクは `infrastructure: landBorder | bridge | tunnel | seaRoute` と `travelMode: walk | bicycle | roadVehicle | rail | ferry` の組み合わせで扱う。これはコード内の判別値であり、content/schema の新規契約にはしない。
- 閉鎖時は移動前に主人公を止め、座標を変えず、行き先と不足条件を会話で示す。
- 開放時は入口通過を既存の県外衝突タイルより優先し、演出完了後に対象県へ切り替える。
- 初回の正規進入では、対象県の開始地域を飛ばさない安全な到着地点を使う。必要な県内移動演出を終えたあとにだけ操作を返す。開発者モード、または到着県攻略後の再訪では、反対側入口の1マス内側へ着く。
- 通常移動時には `currentIsland`、`currentArea`、`currentMap`、`position`、`visit:<map>` を同じ到着県へそろえて保存する。dev中は現在地だけを確認用に更新し、`visit:*` は保存しない。
- 既存セーブの現在座標が再生成後の入口や壁と重なる場合は、既存の安全な spawn フォールバックで復旧する。
- フェリー・列車・道路移動の演出は共通の軽量オーバーレイで実装し、低スペック端末では静止画＋短いフェードへ縮退する。

## Map and guidance UI

- 県地図には、陸上ゲート、橋、トンネル、駅、港を別アイコンで表示し、開閉状態を区別する。
- 日本地図では、次に使う正規入口の県と交通名を強調する。
- `completeIsland` は次地方の `visit:<first-area>-field` を自動付与しない。最初の物理横断を終えたときだけ、到着県を高速移動先へ追加する。
- 陸続きの次県では、中ボス撃破地点を「ワープ」として表示しない。
- 中ボス・地方ボス後の会話は「ワープホールが現れた」ではなく、対象県名と入口名を案内する。
- ミチルの案内も、県境門・橋・トンネル・列車・船を実際のリンク種別に合わせて分岐する。
- 交通入口を、訪問済み町・ダンジョン・離島の無料ワープ一覧へ混ぜない。
- 航路の料金・時刻・運休情報は表示しない。ゲーム内で現実の運行状況を保証する表現を避ける。
- 事業者ロゴ、固有船体塗装、商標デザインは複製せず、インフラ名・航路名と汎用ドット絵で表現する。
- キーボード、タッチ、マウスの既存操作契約を維持する。

## Save compatibility

- `GameState` の schema version は上げない。
- 新しい保存フィールドは追加せず、既存の `eventsDone`、`areaSigns`、`islandsCleared`、`counters` から開閉を導出する。
- `midboss.<area>` のある旧セーブ、`areaSigns` だけがあるさらに古いセーブ、順番変更対象県をすでに攻略済みのセーブを閉じ込めない。
- 旧実装が地方クリア時に自動付与した次県の `visit:*` は削除せず、そのセーブだけの既得高速移動として維持する。新規進行では自動付与しない。
- 地方境移動時に `currentIsland` も対象県へ更新する。エクスポート後の再インポートで整合性検査を通ること。
- 攻略順変更前の旧セーブでは、完了済み県を新順番で再要求せず、新順番の最初の未完了県を次の正規目的地として計算する。旧順序の各prefixで、直前に完了済みの入口からその未完了県へ進める移行表をテストで固定する。

## Tech stack

- TypeScript
- Phaser 3 field runtime
- Tiled-compatible generated JSON maps
- Preact field/map overlays
- Vitest unit and generated-map audits
- Playwright end-to-end tests
- Existing deterministic RNG and generated-data workflow

新しいランタイム依存、外部API、位置情報、認証情報は追加しない。

## Project structure and ownership

- `scripts/data/`: 正規の都道府県隣接データと9つの実在交通リンク
- `scripts/terrain/`: 共有境界候補、入口候補、相互到着地点を求める純粋な地理ロジック
- `scripts/scaffold-maps.ts`: ゲート、駅、橋・トンネル入口、港、spawn、道路を `maps/*-field.json` へ生成
- `src/core/progression/route.ts`: 攻略順、県完了、リンク解放、旧セーブ互換の純粋判定
- `src/core/progression/island.ts`: 地方クリア時の次県 `visit:*` 自動付与を廃止
- `src/scenes/overworld/`: 県間リンクモデル、移動判断、位置保存、地図モデル、案内モデル、移動演出
- `src/scenes/Overworld.ts`: Sceneライフサイクルと演出の調停だけを担当
- `content/world/japan.json`: 承認済みの地方内攻略順
- `content/i18n/ja.json`: 閉鎖・開放・乗車・乗船・案内文
- `tests/unit/`: 純粋判定、全国生成物、交通カタログ、保存互換の検査
- `tests/e2e/`: 通常進行、開発者モード、往復、再読込の実ブラウザ検査

`maps/` は `pnpm scaffold:maps --force` の生成物としてのみ更新し、直接編集しない。`schemas/`、`contracts.ts`、教材問題データは変更しない。

## Code style and architecture constraints

- `src/core/` は Phaser・Preact に依存しない。
- 地理配置と解放判定は純粋関数へ分け、巨大な `Overworld.ts` に新しい計算責務を直接足さない。
- 乱数が必要な選択は既存の決定論的手段を使い、`Math.random` を使わない。
- 県名・交通名・表示文はコードへ直書きせず、正規データとi18nから取得する。
- 同じ入力から常に同じ入口座標が生成される。
- 既存の県内 `regionGate`、町・ダンジョン・離島 transition、地図ワープを壊さない。

## Implementation plan

1. **進行契約をテストで固定**
   全10地方の入口表、5地方の新順番、リンク解放表、旧セーブprefix、`dev:all`、`currentIsland`、高速移動の初回横断条件を赤テストにする。
2. **正規交通データと全国生成監査**
   86陸上リンクと9交通リンクを2軸の純粋データにし、両端・種類・現行ソース・安全spawnを検査する。新しい攻略順に合わせて地域ボスと推奨レベルを決定論的に再配分する。
3. **マップ生成とランタイム移動**
   入口と接続道路を正規生成し、共通 `interPrefectureLink` で閉鎖、開放、往復、到着保存を実装する。地方クリア時の次県自動訪問とdev中の `visit:*` 保存を止める。
4. **地図・会話・移動演出**
   アイコン、目的地案内、ワープ文言の除去、スキップ可能な橋・鉄道・船の演出を追加する。
5. **全国回帰と実ブラウザ確認**
   生成物監査、単体、コンテンツ検査、ビルド、9交通リンクのデータ駆動E2Eを実行し、統合済みブランチの4174で確認できる状態にする。

各段階を独立コミットにし、失敗時に原因を切り分けられるようにする。承認前には実装へ進まない。

## Testing strategy

### Red-first contracts

- 全国の正規陸上リンクに相互ゲートがない現状を、生成物テストで先に失敗させる。
- 9交通リンクの入口・反対側・種類が存在しない現状を、カタログテストで先に失敗させる。
- 閉じた県間リンクへ触れると座標が変わる現状を、移動単体テストで先に失敗させる。
- 地方境移動で `currentIsland` が更新されない現状を、位置保存単体テストで先に失敗させる。
- 旧攻略順を前提にするテストを、新しい地理連続順へ更新して意図的に失敗させる。
- 地方クリアだけで次県の `visit:*` が立つ現状と、dev移動で `visit:*` が残る現状を、保存単体テストで先に失敗させる。

### Unit and generated-map audits

- 86陸上リンクすべてに2方向のゲートと実在する相互spawnがある。
- 9交通リンクすべてに正しい県、入口種別、双方向到着地点、解放条件がある。
- `infrastructure` と `travelMode` の組み合わせが各リンクの地理と演出に一致する。
- 各門は自県の共有境界、各港は自県の海岸側、各橋・トンネル・駅は対応県の歩行可能地にある。
- 通常の初回到着は県内進行を飛ばさず、再訪と開発者モードでは反対側入口へ着く。
- 門以外の `x`、海、湖は従来どおり衝突する。
- 入口がボス、県内関所、町入口、イベント、宝箱と同じマスを共有しない。
- 通常、`midboss`、legacy `areaSigns`、非物語リンク、跨地方、dev on/off の開閉表を純粋関数で固定する。
- 四国クリアだけでは愛媛―大分航路が閉じ、熊本完了時に開く。福岡・佐賀・長崎・熊本を飛ばせない。
- 松山―小倉など廃止済み航路を正規カタログに含めない。
- 地方クリアでは次県の `visit:*` が増えず、正規入口の初回通過後だけ増える。dev通過では増えない。
- 甲信・東海・近畿・中国・四国について、旧攻略順の全prefixから最初の未完了県へ進め、完了県を再要求しない。
- 新攻略順に合わせた地域ボスレベルが全地方で単調増加する。
- 県地図の入口表示、ワープ表示の除去、ミチル案内の分岐を固定する。
- 到着時の area/island/map/position と旧座標フォールバックを固定する。

## Boundaries

### In scope

- 全国86組の陸上県境リンク
- 9組の実在する橋・トンネル・鉄道・航路リンク
- 地理的に連続させるための甲信・東海・近畿・中国・四国の攻略順と難易度順の修正
- 県境門・交通入口の生成、表示、開閉、往復移動
- 通常進行、旧セーブ、開発者モード
- 地図・会話・ミチル案内・短い移動演出
- 次地方の自動訪問を廃止し、初回物理横断後だけ高速移動を解放すること
- 地方境移動時の保存整合性修正
- 生成物・単体・E2Eによる全国検証
- `docs/00_GAME_DESIGN.md` のワープ前提を、承認済み仕様へ更新

### Out of scope

- 47県を1枚の連続フィールドへ統合すること
- 実距離どおりの橋・トンネル・航海を全編プレイさせること
- リアルタイムの運航状況、時刻、料金、予約、外部API
- 事業者ロゴ・車両・船体デザインの忠実な複製
- 空路、国際航路、今回列挙していない観光航路の追加
- 県ごとに複数の陸上県境道路を作ること
- 既存の県内離島フェリーを全面改修すること
- セーブschema、content schema、質問contract、依存パッケージの変更

## Success criteria

- 陸上で隣接する全86組に、正しい共有境界上の相互ゲートが1組ずつある。
- 北海道・四国・九州・沖縄を含む章間移動に、実在する交通だけを使う。
- 9交通リンクが現実の両端と種類に一致し、廃止済み航路や架空の橋を含まない。
- 通常プレイで章・地方・県内地域の進行を飛ばせない。
- 地方内の連続県は、ワープではなく県境門または実在交通で移動できる。
- 全10地方の入口が章経路表どおりにつながり、次地方の最初の県を飛ばさない。
- 開発者モードでは正規進行を汚さず、全県境門と全交通リンクを利用できる。
- 門・交通通過、逆走、再読込、セーブ書き出し・再取込で現在地が壊れない。
- 県地図、日本地図、案内文が実際の移動方法と一致する。
- 全国生成物監査、対象E2E、全必須検査が成功する。
- 4174の実画面で入口が地理に合う場所に見え、海上の門、重なり、即時跳ね返り、学習順の飛び越しがない。

## Assumptions requiring approval

1. 「全国の県境」は、物語順だけでなく実際に陸上で隣接する86組すべてを指す。
2. 海越しは物語に必要な正規経路と代表的近道として上記9組を実装し、架空の門と従来の県間ワープを廃止する。全国の全航路を網羅するものではない。
3. 青森―北海道は、道路門ではなく北海道新幹線・青函トンネルとして表現する。
4. 中国から四国への正規入口は岡山―香川の瀬戸大橋、四国から九州への標準導線は愛媛―広島―山口―福岡とする。愛媛―大分航路は熊本完了後の近道にする。
5. 県間の不自然なワープをなくすため、甲信・東海・近畿・中国・四国の地方内攻略順を表のとおり変更し、難易度を再配分する。教材内容そのものは変えない。
6. 地方ボス撃破だけでは次県を高速移動先へ加えず、最初の物理横断後に解放する。旧セーブの既得 `visit:*` は維持する。
7. 現実の交通を学べることを優先しつつ、長距離区間は短い演出へ圧縮する。
8. 初回到着の安全性と学習順を、完全対称な出現位置より優先する。入口は現実の到着県に置き、開始地域外なら明示的な県内移動演出を挟む。

## Approval checkpoint

上の8前提を承認後、Implementation planの順にテスト駆動で実装へ進む。特に **地方内攻略順の変更**、**初回高速移動の廃止**、**四国から九州へ入る標準導線** は進行仕様に影響するため、承認前にはコード・マップ・教材データを変更しない。
