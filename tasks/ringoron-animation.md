- リンゴロン1体のみ。待機4コマ（葉の揺れ・瞬き）、攻撃4コマ（構え・体当たり・着地）。
- 背景透過、同じパレット・輪郭・顔を維持。作業シートは128px角×8コマ。32pxへの強制変換なし。
- 戦闘の敵・仲間に適用。画像が読み込めなければ従来の静止画へ戻る。
- 攻撃は既存イベントと連動。攻撃後に待機へ戻り、戦闘終了・KO時は止める。
- セーブ・戦闘計算・他キャラ・将来の全体高画質化は変更しない。

## 手順・検証

1. 参照画像に基づく画像生成と目視確認。
2. 透過スプライトシートを保存し、専用の小さな戦闘描画ヘルパーで再生。
3. Vitestで対象外フォールバック、シート選択、アニメーション定義を検証。
4. Playwrightで待機のフレーム変化、実際の敵攻撃後の復帰、KO・再戦、PCと横向きスマホを確認。
5. `pnpm lint`, `pnpm check:architecture`, `pnpm test`, `pnpm validate:content`, `pnpm build`。

## 画像生成記録

- built-in imagegen 使用。falの課金生成・新しいプロバイダー設定・OmniRoute経由送信なし。
- 参照: アート資料室 `pixels/aomori-ringoron.png`。
- プロンプト: 赤いリンゴ、茶色の茎と緑の葉、縦長の白黒の目、ピンクの頬、小さいU字口を固定。中程度の粗さのピクセル表現、透過4列×2行、文字なし。上段は通常・葉の揺れ・瞬き・復帰。下段は構え・前傾・空中の体当たり・着地。手足や装飾を追加しない。
- 元画像は `docs/verification/ringoron-animation-20261027/generated-source.png`、ランタイム用は `assets/sprites/animations/aomori-ringoron-v1.png`。nearest-neighborで等セルの512×256に整形。
- AI生成差分は手描きの厳密な同一形状ではない。試作として実ゲームサイズで確認する。

## 実装・確認記録

- スプライトシートの登録と再生は `src/scenes/battle/monsterAnimation.ts` に分離。
- リンゴロンのみ敵・仲間をImageからSpriteに切り替える。既存の表示サイズ、戦闘イベント、セーブ形式を維持。
- 待機は5fps・1.2秒のループ間隔。通常攻撃・攻撃わざは10fpsで再生後、待機に戻る。専用の被弾・勝利差分は今回未制作。
- 対象限定設定を反転させる変更でユニットテスト2件の失敗を確認し、元へ戻して成功を確認した。
- 必須検査はlint・architecture・コンテンツ検証・buildを通過。全ユニット165ファイル・1700件成功（攻撃わざへの接続前）。接続後は関連7件とPC実戦闘E2Eが成功。
- PC・スマホの通常攻撃→待機復帰→KO停止、画像リクエスト失敗時のフォールバックはE2Eで確認。最終統合後に全検査とE2Eを再実行する。
- E2Eは出題結果だけ固定し、UIから実際のわざを選ぶ。敵の通常攻撃を確実に確認するため検査用シードを固定。わざ・KOは実イベントの描画経路も直接検証する。
- 既存御三家3体のPC・スマホ表示も回帰検証済み。
- 生成画像は権利台帳にholdで追加。公開の権利承認は行っていない。今回の配信先はローカル確認用ゲームだけ。
- GIFは差分確認用で、ゲームの待機間隔・位置移動とは異なる。原本・GIF・PC/スマホの画面は `docs/verification/ringoron-animation-20261027/` に保存。
- Graphifyはローカルcode-onlyで関連22ファイルを更新確認（264 nodes / 760 edges）。外部LLM未使用。
