# 問題画面の等比縮小と全件レイアウト検査

## 承認済みの要求

小さい画面でも文字・図・操作部を同じ割合で縮小し、時計だけでなく全問題の見切れを調査・修正する。今後の再発を自動検査で防ぐ。
スクロールで届くことを、枠内に表示できていることの代わりにしない。

## 設計と影響範囲

- 全9形式を登録するrenderer registryに共通viewportを適用。ゲーム・Playground・監査画面のすべてが同じ表示経路を使う。
- 基準幅960pxで問題内容をレイアウトし、必要な高さを計測。実際の枠の幅と高さの両方に収まる単一の倍率を適用する。
- 時計・文字・回答ボタン・入力欄・余白・線を含めて縮小。形式別の小画面縮小とスクロール逃避を整理する。
- 採点・問題本文・セーブ・contracts.tsは変更しない。地図・なぞりのポインター座標は拡大縮小後も正しいことを確認する。
- 既存全件監査を強化。manifestの全問題を基準枠・小画面・横長の小画面で検査し、問題文、画像、回答欄の見切れ・内部クリップを失敗にする。
- 全件監査の結果を件数・画面サイズ付きで保存。日常CIは代表例と変更関連、全件監査は手動/nightlyで継続する。

## 作業順と合格条件

1. 現行の固定px・画面依存CSS・監査条件を調べ、共通viewportのテストを先行する。
2. 共通表示を実装し、時計・長文・表・画像・入力・地図・なぞり・実験を確認。
3. 全問題を複数サイズで検査し、見つかった問題を修正して再検査する。
4. check:fast、関連unit/E2E、build、実ブラウザでユーザーの時計問題を確認。
5. レビュー後push・mergeし、4174の正規プレビューを最新ビルドで起動する。

## 再発防止

- 正規の表示経路を一本化し、新形式も登録時に自動で等比縮小される。
- 初期画面だけでなく結果・解説やリサイズ後も同じ倍率が保たれることを検証する。
- 縦横比が変わるケース、文字と画像の倍率一致、キャンバス入力を回帰テストにする。

## 実装・検証結果（2026-11-04）

- registry経由で全9形式に共通viewportを適用。基準幅960px・内容の自然高さを単一倍率で表示し、ResizeObserverで枠と内容の変化に追従する。
- 時計、表、なぞりなどの画面依存の個別縮小と、問題内のスクロール前提を除去。ふりがなの有無による入力問題文の二重表示も修正。
- manifest全7,928問（Playgroundの7,911問とサンプル17問）を960×540、720×405、390×219、844×390で描画。計31,712通り、見切れ・内部クリップ・画像読込・表示領域ゼロの異常0件。
- 最終ブラウザ検査39件成功。全9形式の実ResizeObserverリサイズ、時計・文字・ボタンの倍率一致、縮小地図の採点、なぞり座標、表への入力、小画面の解説、実験の状態遷移を含む。
- `pnpm check:fast`、`pnpm typecheck:tests`、`VITE_NQ_DEV_TOOLS=1 pnpm build`成功。全単体テスト237ファイル／2,243件成功後、追加したruby回帰を含む関連7件も成功。
- 倍率計算をminからmaxへ変えるmutationで回帰テスト失敗を確認し、復元後に成功。独立レビューのRequired指摘は解消済み。
- CIで全9形式の回帰検査を必須化し、公開処理もその成功を待つ。全問題4サイズ監査はnightly／手動で実行しJSONレポートを保存する。
- ゲーム本体の「必殺技→問題→採点→ターン進行」E2Eも成功（別途1件）。
- アプリ内ブラウザの幅487pxで時計・全選択肢・解説が枠内に収まることを目視確認。

## 検証範囲の限界

全件は描画監査、解答操作は代表ケースを検証。実機スマートフォンとSafariでの操作は未検証。極小画面では全体を等比縮小するため文字も小さくなる。
