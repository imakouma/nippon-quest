# 問題フォルダ整理・復元: 実装計画

承認済みの `SPEC-folder-organization.md` と `SPEC-folder-recovery.md` を対象とする。問題ファイルは移動・削除せず、開発画面のフォルダ構成だけを保存する。フォルダ削除は復元が動く状態になるまで公開しない。

## 設計と順序

1. フォルダと問題の所属を表すデータと検証処理を用意する。教科・学年を変更できないこと、所属を失った問題が「未整理」に残ることをテストする。
2. 開発環境専用の保存処理を追加する。ローカル限定、入力検証、保存競合の検出、一時ファイルを利用した安全な更新をテストする。読み込み失敗時は既存データを上書きしない。
3. 構成の編集前に戻せる履歴と、再起動後も残る復元ポイントを接続する。復元直前の状態も戻せるようにする。
4. 一覧 UI に学年より下のフォルダ作成・削除・問題移動と、取り消し・復元を加える。削除時には名前と問題数を確認し、問題は未整理へ戻す。
5. 実ブラウザで作成・移動・削除・取り消し・保存・再読込・復元を検証し、検索と問題編集が維持されることを確認する。

## 安全上の判断

- 問題 ID、単元コード、問題本文、元の JSON ファイルを変更しない。既存の生成カタログは表示元として利用する。
- 同時編集は保存前の版を比較して検出し、競合時は変更を上書きせず知らせる。
- 復元データを壊さないよう、異常な入力や保存失敗では操作を中断する。復元ポイントはフォルダ構成に限る。
- 個人の既存の未コミット変更はそのまま保持する。

## 確認

各段階で該当する Vitest と Playwright を実行し、最後に `pnpm check:fast`、`pnpm validate:content`、`pnpm build` とブラウザ検証を行う。統合担当が統合後に `pnpm check:full` を実行する。
