# 5・6年生の音読み・訓読みを例文入力へ

- 5年193問・6年191問を音読み/訓読みそれぞれ移行（計768問）。
- 1〜4年と同じく、例文の対象漢字一字の読みを入力。送り仮名は欄の外へ表示する。
- 問題数・ID・単元・分類と、各分類で読みが存在する全漢字を維持する。
- 既存の入力UI、IME対応、ひらがな以外を入れた時だけの案内を再利用する。
- 1〜4年の問題、書き取り、契約/schemaは変更しない。

## 実装と検証

1. 全学年の入力形式・読み・送り仮名・保存データを検査するテストに拡張。
2. 学年/分類別の例文を追加。生成器を全学年入力へ統一し、不要な選択肢生成を削除。
3. 内容全件監査、関連検査、各学年/分類の画面採点と長い例文の表示を確認。
4. 最新共有版を含む状態で完全検査し、統合後に4174の問題レビューを開く。

## 完了記録

- 5・6年の768例文を追加し、読み問題の生成を全学年で入力式に統一。1〜4年の問題JSONと書き取りに差分なし。
- 「承る」「政」のような長い読みも見切れないよう、読み入力欄を入力文字数に合わせて広げる。
- 「貴い」「尊い」の「とうと／たっと」、「私」の「わたし／わたくし」、「得る」の「え／う」を正解として受け付ける。単漢字・単一解答・該当する正解語に限定し、「得る」は終止形だけに適用して、音読みや他の問題の採点は保つ。
- 新規例文は全件、正規の読み・対象学年・送り仮名・一字だけの対象漢字・問題数・一意性を検査。
- 全学年の入力形式テストを先に拡張し5・6年の4ケース失敗を確認。読みのゆれ4ケースと長い読みのブラウザ表示も修正前の失敗を確認した。
- 関連検査34ファイル279件、check:fast、開発サーバーのブラウザ検査66件が成功（320/1440幅、正誤判定、IME、不正入力、長い読みと例文、共通問題枠）。
- Graphifyをコードのみで更新。依存追加・契約/schema変更なし。
- 完全ゲート（check:full）成功: 266ファイル2433テスト、全件内容監査、型検査、ビルド、性能予算。最終レビューで「眼」「腹」の例文を明確化し「得る」の別読みを追加したため、関連34ファイル280テスト・check:fast・内容監査付きbuild・性能予算を再実施し成功。ビルド版E2Eも17件成功（5・6年の全4分類、長い入力、別読み、修正した例文、320/1440幅）。
- 採点ガードの「得る」条件を反転させてテスト失敗を確認し、元に戻した。
- 画面証跡: `test-results/g5-onyomi-1440.png`、`test-results/g6-kunyomi-1440.png`、`test-results/g6-reading-0054-320.png`。
- 五軸レビュー: 依存/契約変更なし、生成処理を削減、入力検証/IMEを維持、正解の別読みと長い入力を回帰検査。マージを妨げる指摘なし。
